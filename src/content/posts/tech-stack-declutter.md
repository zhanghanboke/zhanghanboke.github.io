我的备忘录里躺着一张清单：Java、Python、C++、Go、Rust。

五门语言，每一门都有非学不可的理由。Java 岗位最多，Python 好上手还能顺手碰 AI，
C++ 是考研教材指定的语言，Go 据说薪资高，Rust 很酷、而且听说写起来会上瘾。

但我从来没问过自己一个问题：**学到什么程度算够？**

## 没有停止线，就等于永远学不完

结果是，五门语言我都停在了第一个山头。

Java 语法看完一遍，觉得"差不多了"，转去看 Python；
Python 写了几个脚本，又觉得 C++ 才是考研的根本，回头翻指针；
翻到一半听说 Go 的并发模型很优雅，又去看 goroutine……

每一次切换都有正当理由，每一次都只走了一小段。
一年下来，五门语言我都能说个大概，但**没有一门扛得住追问**。

## 把它们分成三层之后，事情清楚了

后来我把自己想学的东西按"作用"重新排了一遍：

```text
┌────────────────────────────────────────┐
│ L3 加分层   Go / Rust / AI 工程化      │  ← 决定上限，决定不了有没有 offer
├────────────────────────────────────────┤
│ L2 应用层   Java 生态 + 项目           │  ← 决定简历上有没有东西可写
├────────────────────────────────────────┤
│ L1 基础层   408 四门 + 数学 + SQL      │  ← 决定能走多远
└────────────────────────────────────────┘
```

排完之后定了一条铁律：**L1 不稳，不许碰 L3。**

任何时候发现自己"在学 Go，但操作系统还讲不清进程调度"，就立刻停手。
这条规则听起来很基础，但它砍掉了我过去大半年的无效折腾。

## 给每门语言划一条"停止线"

第二件事，是给每一门写出**明确的停止条件**——到了就停，再往下投入就是浪费。

| 语言 | 定位 | 停止线 |
| --- | --- | --- |
| **Java** | 唯一的深钻对象 | 没有停止线，但有个前提：基础层没达标时，不许新增 Java 组件 |
| **Python** | 工具，不是求职方向 | 能独立写出 500 行以内的实用工具，就够了 |
| **C / C++** | 为考研服务，不为就业 | 约 150 小时封顶，能读懂教材里的 C 代码、能写中等算法题就停 |
| **Go** | 加分项 | 初试结束之后再动手，2 周速通语法 |
| **Rust** | 兴趣期权 | 只允许读前 10 章、写一个 300 行以内的小工具 |

划线的过程比我想象的难受，因为每一条线都在说"**我不学这个了**"。

比如 Python 那条 500 行的线——超过这个规模还在写 Python，说明我在逃避主线。
比如 Rust 那条"只准写玩具"的线——一旦发现自己在用 Rust 认真重写一个正经项目，立刻停。

但难受完之后，是难得的轻松。过去那种"还有四门语言没学"的焦虑，
变成了"**现在只有一件事要做**"。

## 两件事抢时间的时候

现在我按这个顺序裁决：

1. 这个东西能同时出现在**试卷**和**面试问答**里吗？ → 优先
2. 能变成 GitHub 上一段**可展示的代码**吗？ → 次优先
3. 能写进简历的技能栏吗？ → 再次
4. 只是"听说很火""觉得有意思"？ → 推迟

第 4 条砍掉的东西最多。

## 断舍离之后剩下什么

剩下一条很窄的路：**基础层 → Java → 项目**。

以前的清单是五门语言，现在的清单是一件事。听起来是减法，
但我觉得自己反而第一次真正开始学东西了——因为不用再为"要不要学那个"消耗决策力。

Go 和 Rust 没有被删掉，只是被排到了两年之后。
希望到那一天，我是带着一个具体问题去学它们，而不是因为"听说很火"。
