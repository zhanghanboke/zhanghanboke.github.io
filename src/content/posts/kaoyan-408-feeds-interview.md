决定考研之后，我有过一段纠结期。

纠结的点很具体：如果把晚上和周末都投给数学和专业课，
那手上的 Java、项目、八股怎么办？会不会就此停下来？

后来我把 408 的四门课和后端面试的考点摆在一起，逐条对照了一遍。
对照完发现，这个纠结根本不成立——**它们不是两件事，是同一件事的两种问法。**

## 数据结构 ↔ 手撕算法 + Java 集合源码

| 408 考点 | 面试里的对应物 |
| --- | --- |
| 线性表 / 链表 | `LinkedList` 源码、手写 LRU（LeetCode 146） |
| 栈 / 队列 | 单调栈、线程池的任务队列选型 |
| 树 / 二叉树 | `TreeMap` 红黑树、**B+ 树** |
| 查找 | **HashMap 源码**：扰动函数、扩容、树化阈值 8 / 退化 6 |
| 排序 | `Arrays.sort()` 为什么基本类型用双轴快排、对象用 TimSort |

这张表里最值钱的一格是 **B+ 树**：408 考它，MySQL 索引也考它。学一次，用两次。

还有一条习惯是后来才养成的：**每学一个数据结构，就去翻一眼它在 Java 里的实现。**
花二十分钟，换来一道 408 题加一个面试追问点。

## 计算机组成原理 ↔ JVM 与并发底层

计组是四门里最难直接变现的，但有一格特别值钱：

| 408 考点 | 面试里的对应物 |
| --- | --- |
| 数据表示（补码 / 浮点） | `0.1 + 0.2 ≠ 0.3`、BigDecimal |
| Cache 映射 | CPU Cache 行、**伪共享**、`@Contended` |
| 指令重排 | `volatile` 的可见性与有序性 |
| 中断 / DMA | 零拷贝、`mmap`、`sendfile` |

拿 `volatile` 举例。大部分人能背出"保证可见性，不保证原子性"，
但它的底层是 **MESI 缓存一致性协议 + 内存屏障**——而这正好是计组里 Cache 那一章的内容。

把这两头接上，就能从 `volatile` 一路讲到 Store Buffer 和内存屏障指令。
这一题在很多面试里是能定档的。

## 操作系统 ↔ Java 并发（变现率最高的一门）

如果只让我挑一门先学，我选操作系统。因为它几乎一对一映射到并发八股：

| 408 考点 | 面试里的对应物 |
| --- | --- |
| 进程 / 线程 | 线程 vs 协程、虚拟线程 |
| 调度算法 | 线程池的工作队列与拒绝策略 |
| **同步互斥 / PV 操作** | `synchronized`、AQS、`ReentrantLock`、`Semaphore`、`CountDownLatch` |
| 死锁（四个必要条件） | `jstack` 排查、数据库死锁 |
| 内存管理 / 虚拟内存 | JVM 内存区域、OOM 类型、堆外内存 |
| **IO 管理** | `select` / `poll` / `epoll`、Reactor、Netty |

按面试变现率排，我的优先级是：**操作系统 > 数据结构 > 计算机网络 > 计算机组成原理**。
注意这不是按考试分值排的。

## 计算机网络 ↔ HTTP / RPC / 分布式

网络这一门，现在面试已经不问原文了，问场景：

- ❌ "请说说 TCP 三次握手"
- ✅ "一个 RPC 调用超时了，你怎么排查？"
- ✅ "TCP 粘包怎么解决？你的框架是怎么处理的？"

所以每学一个协议，可以多问自己一句：**如果我用它设计一个 RPC 协议，会怎么做？**

同一个问题能提两处——408 的分数，和手上项目的质量。

## 但也不是所有知识点都值得同等投入

对照完会发现，交集之外还有两块：

**只考不面**（408 有、面试不问）：计组的定点运算、总线时序、外部排序、败者树。
→ 做完选择题、记住结论就够，**不要深挖原理**。

**只面不考**（面试必问、408 不考）：MySQL、Redis、Spring、MQ、分布式事务。
→ 这块必须单独排时间，而且**408 考满分也救不了它**。

## 所以不纠结了

以前我把考研和技术当成两个抢时间的对手。
现在看，它们更像一条路的两种走法——**基础层投入一次，在初试和面试上各变现一次。**

真正的浪费不是"考研占用了技术时间"，
而是把 408 当纯考试背完，面试时又想不起它和八股之间有什么关系。

每学完一章，做两件事就够了：写一篇「考点 ｜ 面试会怎么问」的笔记，
再找一道对应的题做掉。三十分钟，把两张网连上一根线。

连得多了，面试时的"反应速度"自然就出来了。
